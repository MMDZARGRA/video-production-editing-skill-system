# Resource Database

Add only resources you have used or evaluated. A resource is useful when it improves a decision or practice drill—not because it is popular.

| Area | Strong source types | What to capture | Evaluation question |
|---|---|---|---|
| Story & editing | Films, edit breakdowns, interviews with editors | Beat map, cut rationale, retention observation | What changed at each edit? |
| Camera & lighting | Manufacturer manuals, ASC resources, tested tutorials | Setup diagram, settings, result | Can I reproduce this in my space? |
| Audio | Production sound handbooks, DAW documentation | Mic placement, noise issue, repair route | Is dialogue clearer without sounding artificial? |
| Color | Camera/colour-management documentation | Input transform, correction order, export setting | Does it preserve natural skin and consistency? |
| Motion & type | Software documentation, title sequences, brand manuals | Grid, type scale, timing, safe-area rule | Is it readable at viewing speed? |
| Platform delivery | Official platform specifications and creator documentation | Current spec date, format, caption requirement | Is this current and verifiable? |
| Analytics | Native platform analytics documentation | Metric definition, review cadence | Does it change the next creative decision? |
| AI & rights | Tool terms, copyright office guidance, client policy | Provenance, disclosure, permission constraint | Can this be defended and recreated safely? |

## Entry schema

`Title | URL/source | creator/publisher | date checked | domain | level | key lesson | practice drill | evidence | confidence | rights/terms note`

## Reference review rule

Date-check platform specs and AI terms before each campaign. Prefer primary sources for specifications, safety, licensing, and technical workflow. Label anecdotal advice as an example, not a rule.
